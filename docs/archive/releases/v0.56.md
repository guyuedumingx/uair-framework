# UAIR v0.56 Release Status

## Decision

```text
Source/npm alpha candidate:
READY FOR EXTERNAL TESTING

Production-grade 1.0:
NOT YET
```

v0.56 deliberately does not add business concepts to Runtime Core.

## Architecture boundary clarified

The repository now has an explicit four-layer contract:

```text
Runtime Core
Runtime adapters
Optional platform/tooling packages
Domain/reference packages
```

`@uair/oa` and approval remain domain/reference code. RBAC, tenant policies,
operator tooling, Agent, MCP and UI remain optional outer packages.

A personal local UAIR application can start with only `@uair/core` and local
Storage.

## Developer-experience correction

`create-uair` previously still generated stale `^0.37.0` dependencies and
included UI in the default template.

v0.56 fixes this:

```text
create-uair
→ @uair/core ^0.56.0 only
→ runnable durable hello Workflow
→ JsonFileStorage
→ no RBAC / tenant / OA / UI requirement
```

This is now enforced by the DX gate.

## Operability P1 completed in this release

New optional package:

```text
@uair/ops
```

It provides host/operator helpers for:

```text
structured error classification
health/readiness aggregation
Runtime storage health
worker-registry health
graceful worker drain
dead-letter recovery
```

None of these concepts were added to Runtime Core.

SQLite and PostgreSQL reliable-queue adapters expose an operator-level
`requeueDead()` action. The generic Core `JobQueue` contract was intentionally
left unchanged.
