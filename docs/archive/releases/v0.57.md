## Main change: durable identity without configuration-heavy DX

v0.57 separates two questions that should not be conflated:

```text
Does a durable Workflow need stable identity?
YES

Must a developer write id + version fields everywhere?
NO
```

The compact default API is:

```ts
const checkout =
  workflow(
    "commerce.checkout",
    async input => {
      ...
    }
  );
```

Runtime semantics:

```text
id      = commerce.checkout
version = 1
```

`version` is written only when a durable evolution boundary needs to be
declared:

```ts
workflow(
  "commerce.checkout",
  {
    version:
      "2"
  },
  ...
)
```

Ordinary TypeScript functions require no UAIR identity. A stable ID is required
only for durable/replayable Workflow and Component boundaries.

## Identity hardening

Core now rejects:

```text
empty/whitespace Workflow ID
empty/whitespace Component ID
empty/whitespace Workflow version
control characters in durable identity/version
```

It deliberately does not infer IDs from variable names, file names, source
locations or bundler output.

## First-run DX

`create-uair` now generates:

```text
one runtime dependency: @uair/core
one explicit durable ID
zero explicit version fields
zero enterprise packages
tsconfig.json
```

The generated project is automatically:

```text
created
TypeScript compiled
executed
```

during release verification.
